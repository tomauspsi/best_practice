# Costruire un'unica memoria per Claude, Code e Cursor

**Risposta breve.** Un ponte automatico che faccia vedere alla scheda Chat la stessa memoria di Claude Code e di Cursor oggi non esiste: le memorie sono sistemi paralleli e le richieste di unificarle sono ancora aperte e senza risposta ufficiale ([issue #90973](https://github.com/anthropics/claude-code/issues/90973), [issue #98667](https://github.com/anthropics/claude-code/issues/98667)). Il comando `claude mcp serve` esiste ancora, è documentato e ha ricevuto correzioni fino alla 2.1.302 ([documentazione](https://code.claude.com/docs/en/mcp), [CHANGELOG](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)), ma dà alla Chat gli strumenti di Claude Code (Bash, Read, Write, Edit), non la sua memoria, e sposta tutta la responsabilità della conferma sul client. Sulla build Microsoft Store (MSIX) di Claude Desktop il problema più insidioso non è il comando ma il file di configurazione: l'app può leggere un percorso virtualizzato diverso da quello che apre "Edit Config" ([issue #26073](https://github.com/anthropics/claude-code/issues/26073), ancora aperta). La soluzione più solida, quindi, non è un ponte tecnico ma una disciplina: **una sola cartella di file Markdown come fonte di verità**, letta da Code e Cursor tramite `AGENTS.md`/`CLAUDE.md` e skill condivise, e resa visibile alla Chat con il server filesystem ufficiale limitato a cartelle non cliniche. Le cartelle cliniche restano fuori da ogni ponte. Le chat lunghe si evitano chiudendole con un riepilogo scritto nella cartella, perché le singole conversazioni non hanno un archivio nativo.

Legenda usata in tutto il testo: **[Verificato]** = letto in una fonte citata; **[Inferenza]** = mio ragionamento, non confermato da fonti; **[Obsoleto/Conflitto]** = informazione datata o contraddetta. Il report è del 18 ottobre 2026.

## Tre motori, tre archivi: che cosa è condiviso davvero

L'app desktop ha tre schede, e la documentazione le descrive come tre cose diverse: la Chat è "conversazione generale senza accesso ai file", Cowork è "un agente autonomo in background", Code è "un assistente interattivo con accesso diretto ai file locali" ([Desktop quickstart](https://code.claude.com/docs/en/desktop-quickstart.md)). **[Verificato]** Chat e Cowork condividono la stessa "casa" e l'account claude.ai (memoria, plugin, connettori, skill) ([Getting started with Cowork](https://support.claude.com/en/articles/13345190-getting-started-with-cowork)). La scheda Code e la CLI condividono invece `C:\Users\Tommi\.claude` (impostazioni, CLAUDE.md, memoria automatica, skill personali) e `.claude.json` per i server MCP; la pagina delle piattaforme parla di configurazione "condivisa tra le superfici locali", ma solo CLI, Desktop e IDE, non la Chat ([Platforms](https://code.claude.com/docs/en/platforms.md)).

| Elemento | Chat | Cowork | Code tab / CLI | Fonte |
|---|---|---|---|---|
| Memoria claude.ai (riassunto ogni 24 h, per progetto) | Sì | Sì, le sessioni cloud partono da ciò che Claude ricorda | Non documentata | [Memoria e ricerca chat](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context) |
| CLAUDE.md e memoria automatica di Code | Non documentata | Non documentata (solo una nota sugli import) | Sì, a ogni sessione | [Memory](https://code.claude.com/docs/en/memory.md) |
| Skill in `C:\Users\Tommi\.claude\skills` | Non documentata | No | Sì | [Skills](https://code.claude.com/docs/en/skills.md) |
| Skill dell'account claude.ai | Sì | Sì, sincronizzate a inizio sessione | Scaricate in `.claude\skills\synced\` (solo download, dalla v2.1.273) | [Cowork overview](https://claude.com/docs/cowork/overview) |
| Server MCP | `claude_desktop_config.json` ed estensioni | Stessa configurazione Customize | `.claude.json` e `.mcp.json` | [MCP in Claude Code](https://code.claude.com/docs/en/mcp.md) |
| Storico sessioni | Account claude.ai | Account, tra desktop/web/mobile | Lista propria per superficie | [Sessions](https://code.claude.com/docs/en/sessions.md) |

**[Verificato]** Le skill hanno due archivi distinti: quello locale e quello dell'account. La sincronizzazione va solo dall'account verso Code, "mai caricata" nel senso opposto, quindi una skill creata solo in locale arriva a Chat e Cowork unicamente se la carichi tu da Customize ([Skills](https://code.claude.com/docs/en/skills.md)). **[Inferenza]** Ne segue che la copia autorevole delle skill che vuoi usare anche in Chat vive su claude.ai, mentre per Code e Cursor vive in una cartella versionata. Cursor, secondo la sua documentazione, legge anche `~/.claude/skills`, quindi una sola cartella di skill serve a entrambi ([Cursor skills](https://cursor.com/docs/context/skills)).

Per le istruzioni comuni il percorso documentato è `AGENTS.md`: Claude Code lo legge direttamente dalla v2.1.277 se non esiste un `CLAUDE.md`, altrimenti basta scrivere `@AGENTS.md` nella prima riga di `CLAUDE.md` ([Memory](https://code.claude.com/docs/en/memory), [wmedia.es](https://wmedia.es/en/tips/claude-code-agents-md-import-symlink)). Se Cursor legga a sua volta `AGENTS.md` non è stato verificato dalla pagina delle skill. Un esempio dei limiti ancora aperti: le "Istruzioni per Claude" impostate nell'app non arrivano alle sessioni Code, perché esistono solo lato account ([issue #88999](https://github.com/anthropics/claude-code/issues/88999)).

Due punti di conflitto da tenere presenti. Primo, la documentazione di Code dice che la Chat non ha accesso ai file, mentre il Centro assistenza afferma che "Claude Cowork è ora semplicemente Claude" e che Claude decide se una richiesta è una risposta rapida o un compito; nessuna pagina riconcilia le due versioni ([Getting started with Cowork](https://support.claude.com/en/articles/13345190-getting-started-with-cowork)). Secondo, non c'è alcun passaggio ufficiale "continua questa chat in Code": le richieste sono aperte e senza risposta ([#102203](https://github.com/anthropics/claude-code/issues/102203), [#102793](https://github.com/anthropics/claude-code/issues/102793), [#15881](https://github.com/anthropics/claude-code/issues/15881)).

## `claude mcp serve` su Windows e MSIX: funziona, ma il percorso è la trappola

**Stato ufficiale [Verificato].** La documentazione mostra la voce da incollare per Claude Desktop: `"claude-code": {"type":"stdio","command":"claude","args":["mcp","serve"],"env":{}}`, con il consiglio di usare il percorso completo se `claude` non è nel PATH, altrimenti compare `spawn claude ENOENT`. Dice anche che il server "espone solo gli strumenti di Claude Code" e che il client "è responsabile della conferma" delle singole chiamate ([Claude Code MCP](https://code.claude.com/docs/en/mcp.md)). Non risulta alcuna deprecazione: il CHANGELOG cita correzioni in 2.1.288 (lo strumento Agent riportava sempre zero agenti), 2.1.295 (output Bash in background) e 2.1.302 ([CHANGELOG](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)). Sul percorso di Windows, per l'eseguibile installato in modo nativo il percorso è `C:\Users\Tommi\.local\bin\claude.exe` ([Setup](https://code.claude.com/docs/en/setup)); in JSON i backslash vanno raddoppiati. **[Inferenza]** Questa forma esatta non compare in nessuna segnalazione verificata; è la lettura prudente del consiglio "percorso completo".

**Che cosa espone, e con quali limiti.** La documentazione non elenca gli strumenti. Una segnalazione del 2025 ne mostra 16 (Task, Bash, Glob, Grep, Read, Edit, Write, NotebookEdit, WebFetch, TodoWrite, WebSearch, BashOutput, KillShell, Skill, SlashCommand, ExitPlanMode) ([issue #10031](https://github.com/anthropics/claude-code/issues/10031)). Una prova diretta fatta durante questa ricerca, su Linux e con la versione 2.1.302, ne ha trovati 47, senza Glob e Grep e senza nessun `outputSchema`; la stessa prova ha mostrato che gli strumenti girano nella cartella da cui il server è stato avviato e che `Write` ha creato un file senza chiedere conferma al client. Questa prova non ha URL, è stata fatta in una sandbox con probabili permessi larghi e **non dimostra** il comportamento di una installazione Windows predefinita: l'elenco su Windows va riverificato. **[Verificato]** Nessuna fonte dice se CLAUDE.md, memoria automatica o le regole di `settings.json` vengano applicate in modalità `mcp serve`, né se lo strumento Skill carichi le tue skill personali attraverso questo percorso.

**Storia dei bug e che cosa è stato corretto.** Il guasto classico, cioè server "connesso" con zero strumenti, errore `invalid_literal ... outputSchema.type` o interruttore grigio, era un solo difetto: `mcp serve` pubblicava schemi di output con `anyOf` senza `type` di primo livello. Comparve nella 1.0.120 (settembre 2025) e fu corretto nella **2.0.33** (novembre 2025) ([issue #8014](https://github.com/anthropics/claude-code/issues/8014), [#10031](https://github.com/anthropics/claude-code/issues/10031), [#11319](https://github.com/anthropics/claude-code/issues/11319)). Quelle segnalazioni sono chiuse e vecchie di oltre sei mesi: con la tua versione 2.1.299/2.1.302 non dovrebbero riguardarti. Nel 2026 i difetti si sono spostati nel client Desktop: strumenti dichiarati ma mai chiamati in modalità Chat quando dichiaravano un `outputSchema`, segnalati il 22 luglio 2026 anche sulla build MSIX 1.24012.x e dati per risolti in **1.24012.9** il 24 luglio ([issue #79986](https://github.com/anthropics/claude-code/issues/79986)). In Cowork una regressione successiva (claude-code-vm 2.1.227, 11 agosto) rifiutava lo schema `draft-07`, mentre la Chat continuava a funzionare con lo stesso server ([commento](https://github.com/anthropics/claude-code/issues/79986#issuecomment-5261023719)). Lo strumento Agent di `mcp serve` partiva con un registro di subagent vuoto; un collaboratore Anthropic lo ha confermato come bug il 16 agosto ([issue #41973](https://github.com/anthropics/claude-code/issues/41973)).

**[Conflitto]** L'issue #41973 risulta ancora aperta con un commento del 30 settembre ("stesso problema", versione non indicata), mentre il CHANGELOG 2.1.288 dichiara la correzione. Non ho verificato in modo diretto che l'Agent funzioni ora.

**Il percorso del file di configurazione sulla build MSIX.** Qui il quadro è contraddittorio e va controllato sul tuo PC. La documentazione MCP indica `%APPDATA%\Claude\claude_desktop_config.json` e i log in `%APPDATA%\Claude\logs` ([Connect to local MCP servers](https://modelcontextprotocol.io/docs/develop/connect-local-servers)). L'issue #26073, aperta il 16 febbraio 2026, sostiene che sulle installazioni MSIX "Edit Config" apra quel percorso, mentre l'app legge `C:\Users\Tommi\AppData\Local\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude\claude_desktop_config.json`, e ignora in silenzio i server ([issue #26073](https://github.com/anthropics/claude-code/issues/26073)). Anthropic non ha risposto nella discussione. Le soluzioni segnalate: modificare direttamente il file virtualizzato **unendo** `mcpServers` al contenuto esistente senza cancellare `preferences`; oppure disinstallare, creare a mano `%APPDATA%\Claude` e reinstallare ([commento](https://github.com/anthropics/claude-code/issues/26073#issuecomment-3947215273)); oppure un link simbolico, che richiede privilegi di amministratore. Le prove non sono univoche: un utente il 24 agosto ha messo una voce valida nel percorso virtualizzato, ha chiuso l'app dalla barra di sistema e ha comunque letto "No servers added"; un altro il 6 settembre ha trovato il file vuoto ([commento](https://github.com/anthropics/claude-code/issues/26073#issuecomment-5390981401), [commento](https://github.com/anthropics/claude-code/issues/26073#issuecomment-5561237022)). Dipende anche dalla storia del PC: se prima c'era una versione non-MSIX, il comportamento cambia ([commento](https://github.com/anthropics/claude-code/issues/26073#issuecomment-3930916234)). Un'altra segnalazione, la #25600, fu chiusa come "non pianificata" dopo che l'autore passò al programma di installazione diretto ([claudeissues.com #25600](https://claudeissues.com/issue/25600-local-mcp-servers-silently-ignored-when-claude-desktop-installed-from-microsoft)); la stessa pagina riporta anche lo stato "Resolved", quindi la chiusura è ambigua.

Per la tua build 2.42304.0.0 non c'è un esito certo. Una segnalazione sulla stessa build mostra che `chromiumFlags` messi in `%APPDATA%\Claude\claude_desktop_config.json` sono stati applicati, ma il percorso completo è omesso e non prova nulla per `mcpServers` ([issue #102948](https://github.com/anthropics/claude-code/issues/102948)). Un'altra segnala sulla 2.42304.0 una Chat inutilizzabile finché non si cancellano tutti i dati e si reinstalla ([issue #102571](https://github.com/anthropics/claude-code/issues/102571)). **[Inferenza]** Il metodo sicuro è empirico: apri "Edit Config", modifica il file aperto, riavvia davvero l'app (chiudila dalla barra di sistema, non basta la finestra) e controlla in Impostazioni > Developer se compare il server; se no, ripeti nel file virtualizzato e consulta i log in `C:\Users\Tommi\AppData\Local\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude\logs`. La configurazione viene letta solo all'avvio, e una voce rotta può far morire in silenzio le sessioni Code a freddo ([issue #86756](https://github.com/anthropics/claude-code/issues/86756)).

**Altri rischi operativi nelle versioni 2.x.** Sulla 2.42304.0 i tool locali chiamati dalla Chat passano da un ponte con attesa di 60 secondi ("Device ... did not respond within 60s"), che penalizza chiamate lunghe come Bash o Agent ([issue #102940](https://github.com/anthropics/claude-code/issues/102940), aperta il 17 ottobre, macOS, etichettata "invalid"; applicabilità a Windows **[Inferenza]**). Restano aperte segnalazioni su processi MCP duplicati o non terminati (#75574, #88514), su chiamate bloccate se si clicca "Allow once" prima della fine della generazione (#92014) e su aggiornamenti automatici MSIX che chiudono Desktop circa ogni due giorni (#100576): di queste ho visto solo i titoli ([#75574](https://github.com/anthropics/claude-code/issues/75574), [#92014](https://github.com/anthropics/claude-code/issues/92014), [#100576](https://github.com/anthropics/claude-code/issues/100576)). Un'altra segnalazione rilevante per MSIX: i processi della scheda Code vedono le scritture su `%LOCALAPPDATA%` reindirizzate in silenzio sotto `Packages\Claude_*\LocalCache\Local`; la soluzione è scrivere sotto `%USERPROFILE%` ([issue #94254](https://github.com/anthropics/claude-code/issues/94254)). **[Conflitto]** Le sessioni Code della build MSIX hanno avuto problemi di persistenza (#48362, chiusa "non pianificata", su una versione molto precedente) ([claudeissues.com #48362](https://claudeissues.com/issue/48362-bug-claude-desktop-windows-store-msix-code-sessions-silently-fail-to-persist-due)); lo stato sulla tua build è sconosciuto.

**Giudizio.** `claude mcp serve` è tecnicamente l'unico modo documentato per dare alla Chat gli strumenti di Claude Code, ma le guide che lo raccontano sono parziali e una frase circolante, cioè che "Claude Code non può girare su Windows nativo", è **[Obsoleto]**: tu usi già Claude Code 2.1.x su Windows ([ksred.com](https://www.ksred.com/claude-code-as-an-mcp-server-an-interesting-capability-worth-understanding/)). Il wrapper `@steipete/claude-code-mcp` è archiviato dal 15 maggio 2026, con l'ultimo rilascio npm del maggio 2025 e, di default, l'avvio con `--dangerously-skip-permissions`: da considerare abbandonato ([GitHub](https://github.com/steipete/claude-code-mcp), [npm](https://registry.npmjs.org/%40steipete%2Fclaude-code-mcp)). Non ho trovato testimonianze di prima mano (Reddit, Hacker News, Discord) che confrontino i tre approcci su Windows.

## Cartelle per Chat e Cowork: che cosa è ufficiale, che cosa si rompe, che cosa conviene

**Vie ufficiali [Verificato].** Cowork su desktop può leggere e scrivere file nelle cartelle che hai collegato e "solo in quelle", ma l'app deve restare aperta ([Getting started with Cowork](https://support.claude.com/en/articles/13345190-getting-started-with-cowork), [Use Cowork on web, desktop, mobile](https://support.claude.com/en/articles/15520349)). Un Progetto Cowork può essere creato su una cartella esistente e tiene istruzioni, contesto e memoria di progetto, sul solo computer ([Organize your tasks with projects](https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork), [Cowork projects](https://claude.com/docs/cowork/guide/projects)). Sono supportate le lettere di unità di rete mappate, non i percorsi UNC (`\\server\share`, compreso `\\wsl$`) ([Cowork 3P local access](https://claude.com/docs/cowork/3p/local-access); questa pagina riguarda i provider di terze parti e dichiara di rispecchiare Claude Desktop standard). I server MCP locali, invece, si configurano una volta sola e restano: il server filesystem ufficiale ottiene le cartelle come argomenti, e ogni azione "richiede la tua approvazione esplicita", con i permessi del tuo utente ([MCP local servers](https://modelcontextprotocol.io/docs/develop/connect-local-servers)). La documentazione non dice se una cartella collegata a una singola chat resti disponibile nelle chat successive: è dichiarato "non coperto".

**La persistenza delle cartelle di progetto si rompe spesso [Verificato come segnalazione, non come stato attuale].** Una segnalazione di luglio 2026 riferiva cartelle del Contesto di progetto non montate nelle nuove sessioni; fu chiusa il 7 agosto senza causa confermata, con l'autore che non la riproduceva più nella 1.24012.9 ([claudeissues.com #78677](https://claudeissues.com/issue/78677-bug-cowork-folders-attached-in-project-context-are-not-mounted-in-new-chat-sessi)). La variante Windows (`"connectedFolders": []` nelle nuove sessioni) ha segnalazioni dall'8 luglio al 9 settembre, sulla build 1.49585.0, senza risposta dei manutentori; i rimedi riferiti sono riaggiungere la cartella a metà sessione o usare l'estensione Filesystem ([issue #76187](https://github.com/anthropics/claude-code/issues/76187)). Non ho trovato una conferma di ottobre 2026 che sia stato risolto. Un utente ha segnalato che, in quel periodo, l'estensione Filesystem continuava a funzionare mentre i montaggi Cowork fallivano ([issue #76187](https://github.com/anthropics/claude-code/issues/76187)).

**Estensioni `.mcpb`.** Sono pacchetti installabili da Impostazioni > Estensioni, con Node.js incluso nell'app, valori sensibili nel portachiavi del sistema, e un campo `user_config` di tipo `directory` per scegliere le cartelle ([Anthropic Engineering](https://www.anthropic.com/engineering/desktop-extensions), [Centro assistenza](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop)). Sono la via riferita da alcuni utenti MSIX quando il file JSON non viene letto ([commento](https://github.com/anthropics/claude-code/issues/26073#issuecomment-3939610590)). **[Conflitto]** Il post tecnico descrive l'installazione per utenti singoli; la pagina enterprise parla di Team ed Enterprise ([documentazione connettori](https://claude.com/docs/connectors/custom/desktop-extensions)); su Pro/Max l'installazione di estensioni personalizzate è dunque **non confermata**, come lo è l'esistenza di un'estensione Filesystem ufficiale nel catalogo interno. Anche qui le segnalazioni variano per build: alcune estensioni locali `.mcpb` non risultavano annunciate dal ponte ([commento](https://github.com/anthropics/claude-code/issues/79986#issuecomment-5042334322)).

**Strumenti e sicurezza, con il filtro dello studio clinico.**

| Strumento | Che cosa dà | Rischio/limite | Giudizio per te |
|---|---|---|---|
| Server filesystem ufficiale `@modelcontextprotocol/server-filesystem` | Lettura/scrittura limitata a cartelle consentite; strumenti di sola lettura marcati; con Docker si monta una cartella `ro` | Nessun flag di sola lettura documentato fuori da Docker; scritture non atomiche; su Windows va lanciato con `cmd /c` ([README](https://raw.githubusercontent.com/modelcontextprotocol/servers/main/src/filesystem/README.md)) | Scelta di base, su cartelle non cliniche |
| `claude mcp serve` | Bash, Read, Write, Edit ecc. di Claude Code | La conferma è del client; cartella di lavoro decisa da chi lo avvia ([docs](https://code.claude.com/docs/en/mcp.md)) | Facoltativo, dopo, con cautela |
| Desktop Commander | Terminale, processi, file, ricerca | Dichiarato "non è una sandbox": `allowedDirectories` non limita i comandi di shell; log con argomenti non oscurati ([GitHub](https://github.com/wonderwhy-er/DesktopCommanderMCP)); CVE-2025-11489 (sul seguire i link simbolici, gravità bassa, fino alla 0.2.13; correzione nella 0.3.0 non verificata, date contraddittorie) ([SentinelOne](https://www.sentinelone.com/vulnerability-database/cve-2025-11489/)) | Sconsigliato dove ci sono dati clinici |
| Basic Memory | Note Markdown locali con wikilink via MCP, apribili in Obsidian; `uvx basic-memory mcp` | Licenza AGPL-3.0; cloud opzionale a 15 USD/mese; i dati restano locali se non lo attivi ([GitHub](https://github.com/basicmachines-co/basic-memory)) | Buon candidato per la memoria condivisa |
| Server MCP Obsidian (cyanheads) | Lettura e scrittura del vault, con percorsi di lettura/scrittura consentiti | Richiede Obsidian aperto con plugin REST; verifica TLS disattivata di default ([GitHub](https://github.com/cyanheads/obsidian-mcp-server)) | Utile solo se già usi Obsidian |
| Server memory di Anthropic | Grafo in un file JSONL, ricerca per parole chiave | Un file di database dentro una cartella sincronizzata può creare conflitti **[Inferenza]** ([README](https://raw.githubusercontent.com/modelcontextprotocol/servers/main/src/memory/README.md)) | Più povero del Markdown |
| mcp-memory-service, Mem0, Letta | Memorie semantiche locali o ibride | Mem0 usa per default modelli OpenAI **[Inferenza]**: contenuti inviati a terzi; MiniLM di default è orientato all'inglese ([mcp-memory-service](https://github.com/doobidoo/mcp-memory-service), [Mem0](https://github.com/mem0ai/mem0)) | Non per la parte clinica |
| Claude Context (Zilliz) | Ricerca semantica su codice | Richiede un provider di embedding e un database vettoriale; i frammenti indicizzati escono dal PC se il provider è remoto **[Inferenza]** ([GitHub](https://github.com/zilliztech/claude-context)) | Mai sulle cartelle cliniche |

**Regola di sicurezza che discende da tutto questo.** **[Inferenza]**, ma ben fondata: ogni strumento che dà alla Chat accesso al disco lavora con i permessi del tuo utente, quindi una cartella clinica va esclusa per costruzione, non per fiducia. Per `claude mcp serve` pesa anche il rischio di istruzioni nascoste in contenuti esterni: la documentazione stessa avverte della prompt injection per i server che recuperano contenuti dal web ([Claude Code MCP](https://code.claude.com/docs/en/mcp.md)). Due ulteriori attenzioni: le trascrizioni di Claude Code sono salvate in `C:\Users\Tommi\.claude\projects\...\*.jsonl` con conservazione predefinita di 30 giorni ([Claude directory](https://code.claude.com/docs/en/claude-directory.md)), quindi contengono qualsiasi cosa sia stata letta in quella sessione; e la memoria, di qualunque tipo, può ricevere dal modello dettagli identificabili che non volevi scrivere. Le regole deontologiche e il GDPR su dati sanitari vanno valutati da te; qui non li ho analizzati.

## L'assetto consigliato, con costi e passi

**Idea guida.** La memoria non sta nell'app: sta in una cartella di testo che ogni strumento sa leggere. È lo schema ricorrente delle esperienze di comunità: una cartella unica come fonte di verità, un file d'indice breve letto sempre, note dettagliate lette su richiesta, e un passo esplicito di chiusura che scrive un riepilogo ([thread r/ClaudeAI via mirror](https://reddit.sentinel-team.org/posts/1sd9cpj/snapshots/2026-04-09T16%3A41%3A00.47446Z), [blitzmetrics.com](https://blitzmetrics.com/lockdown-files-cowork-memory-system/), [blog.dmcc.io](https://blog.dmcc.io/journal/obsidian-claude-personal-assistant/)). Sono testimonianze singole, non misure. Un dettaglio utile dal caso Obsidian: quando Claude modificava direttamente file in una cartella sincronizzata comparivano scritture parziali ed errori di sync; passare per un server MCP che scrive in modo atomico li ha risolti ([blog.dmcc.io](https://blog.dmcc.io/journal/obsidian-claude-personal-assistant/)). Per questo suggerisco di tenere la cartella canonica in locale e usare Drive come copia di sicurezza, non come luogo di lavoro **[Inferenza]**.

| Passo | Che cosa fare | Costo/compromesso |
|---|---|---|
| 1. Cartella canonica | Creare ad esempio `C:\Users\Tommi\Workspace` con `AGENTS.md` (regole e contesto), `memoria\` (profilo, progetti, diario di lavoro), `skill\`, e inizializzarla con Git. Nessun dato clinico. | Un'ora di lavoro; richiede disciplina nel tenerla aggiornata |
| 2. Code e CLI | Creare `C:\Users\Tommi\Workspace\CLAUDE.md` con la sola riga `@AGENTS.md`; aggiungere la cartella con `--add-dir` o aprirla come progetto. Collegare le skill con una giunzione (`mklink /J`) o una copia verso `C:\Users\Tommi\.claude\skills`. | Le giunzioni non richiedono amministratore di solito; i link simbolici sì **[Inferenza]**. Se la sincronizzazione non regge, lo strumento Rulesync copia invece di collegare ([GitHub](https://github.com/dyoshikawa/rulesync)), ma il suo comportamento su Windows non è verificato |
| 3. Cursor | Aprire la stessa cartella come progetto; lasciare che legga le skill da `~/.claude/skills`. Se `AGENTS.md` sia letto da Cursor va provato. | Doppia registrazione dei server MCP: `~/.cursor/mcp.json` è separato da quello di Claude Code ([mcp.directory](https://mcp.directory/blog/desktop-commander-mcp-complete-guide-2026)) |
| 4. Chat: filesystem | Registrare il server filesystem sulla sola cartella `C:\Users\Tommi\Workspace` (come estensione `.mcpb` se disponibile, altrimenti nel file di configurazione che l'app legge davvero, verificato come sopra). | Ogni chiamata chiede approvazione; non si ottiene indicizzazione semantica, solo elenco, albero e ricerca per nome |
| 5. Chat: istruzione fissa | In Impostazioni, nelle istruzioni personali o in un Progetto della Chat, scrivere una riga: "Inizia leggendo `C:\Users\Tommi\Workspace\AGENTS.md`." Una prova di comunità suggerisce che le istruzioni globali reggano meglio delle cartelle di progetto ([claudeissues.com #78677](https://claudeissues.com/issue/78677-bug-cowork-folders-attached-in-project-context-are-not-mounted-in-new-chat-sessi)). | Dipende dal fatto che la Chat chiami davvero lo strumento; da provare |
| 6. Memoria condivisa (facoltativa) | Installare Basic Memory puntandolo a `C:\Users\Tommi\Workspace\memoria` e registrarlo in Chat, Code (`claude mcp add basic-memory -- uvx basic-memory mcp`) e Cursor. | Un componente in più (Python/uv); AGPL; il README dà solo il percorso macOS per Claude Desktop |
| 7. `claude mcp serve` (facoltativo, dopo) | Solo se serve davvero che la Chat lanci comandi: voce con `C:\Users\Tommi\.local\bin\claude.exe`, avviata su una cartella non clinica, tenendo le approvazioni di Desktop attive. | Massima potenza e massimo rischio; limite dei 60 secondi; nessuna memoria condivisa |
| 8. Chiusura di sessione | Alla fine di ogni lavoro importante chiedere: "Scrivi un riepilogo in `memoria\diario.md` con decisioni, file toccati e prossimi passi." La sessione successiva parte da lì. | Qualche secondo a fine sessione; evita le chat da migliaia di messaggi |

**Perché questo ordine.** La Chat condivide con Code solo ciò che sta nei file, quindi i passi 1-5 danno il 90% dell'effetto con strumenti ufficiali e senza dare alla Chat una shell. **[Inferenza]** Il passo 7 è volutamente in fondo: la guida più citata ammette che in modalità headless non si possono chiedere permessi, e il confine di sicurezza diventa il tuo clic su "Allow" ([ksred.com](https://www.ksred.com/claude-code-as-an-mcp-server-an-interesting-capability-worth-understanding/)).

**Alternativa ufficiale più semplice: Cowork con un Progetto.** Offre cartelle, istruzioni e memoria di progetto senza configurare nulla e usa "la stessa architettura agentica di Claude Code" ([Cowork overview](https://claude.com/docs/cowork/overview)). Il prezzo: vive solo sul PC, non è condiviso con Code o Cursor, la sua memoria è separata, richiede che l'app resti aperta, e su Windows le cartelle di progetto hanno mostrato di non montarsi nelle nuove sessioni (vedi sopra). Se funziona, è un ottimo complemento; non può essere l'unica fonte di verità.

**Archiviazione e chat lunghe.** Il Centro assistenza documenta l'archiviazione per i Progetti, non per le singole conversazioni: l'articolo su eliminazione e rinomina non la cita, e non esiste un articolo "archivio" nella raccolta sulla gestione delle conversazioni ([Delete or rename](https://support.claude.com/en/articles/8230524-delete-or-rename-a-conversation), [raccolta](https://support.claude.com/en/collections/18031977-conversation-management), [Progetti](https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects)). Una richiesta aperta lo conferma dal lato utenti ([issue #63586](https://github.com/anthropics/claude-code/issues/63586), data non visibile). La conclusione si regge sull'assenza di prove, non su una smentita ufficiale. **[Conflitto]** Alcuni blog affermano che esista una sezione di archivio; non hanno supporto ufficiale e sono contraddetti dalle pagine sopra ([leadsource.co](https://leadsource.co/blog/claude-chats-disappeared)). Esiste un'estensione di terze parti, "Claude Archive", che aggiunge la funzione ([Chrome Web Store](https://chromewebstore.google.com/detail/claude-archive/fabmimbljddlpcckdbnnmbmpiddhifdp)): è codice di terzi che gira sulla tua pagina Claude, quindi non la installerei sul profilo dove leggi materiale sensibile. Nella scheda Code l'archiviazione c'è, ma una segnalazione dice che le sessioni archiviate spariscono dalla barra senza vista di ripristino, con i dati ancora in `.jsonl` ([issue #50042](https://github.com/anthropics/claude-code/issues/50042)); in Cowork, chat e progetti archiviati risultano difficili da ritrovare ([issue #22931](https://github.com/anthropics/claude-code/issues/22931)). La finestra di contesto è di 200K token e il consiglio ufficiale è aprire una nuova chat, usare i Progetti (che passano a RAG quando la conoscenza è grande) e spegnere ciò che non serve, perché "strumenti e connettori consumano molti token" ([Usage and length limits](https://support.claude.com/en/articles/11647753-understanding-usage-and-length-limits), [RAG per i Progetti](https://support.claude.com/en/articles/11473015-retrieval-augmented-generation-rag-for-projects)). **[Inferenza]** La pratica più sicura è quindi: riepilogo nel diario, nuova chat, e lasciare la vecchia dov'è; evitare "archivia" su ciò che vuoi ritrovare.

## Che cosa non è stato verificato

La ricerca è stata ampia ma non completa, e conviene dirlo senza giri. Reddit non era raggiungibile direttamente: ho letto due thread di r/ClaudeAI solo attraverso un mirror, con commenti parziali e datati (settembre 2025 e febbraio 2026). Discord non è indicizzato e non ho trovato nulla; forum.cursor.com e Hacker News non hanno restituito thread pertinenti; alcune pagine di claudeissues.com erano bloccate dai robots (uso la copia GitHub quando c'era); le Discussioni di GitHub non erano interrogabili. Molto del materiale "di comunità" è blog di fornitori o SEO, e l'ho segnalato come tale. Restano non verificati: l'esito su Windows dell'elenco di strumenti di `mcp serve` e delle sue regole di permesso; l'effettiva lettura di CLAUDE.md e memoria in quella modalità; la correzione del bug dell'Agent; l'esistenza di un'estensione Filesystem ufficiale e la possibilità di installare `.mcpb` personalizzati su Pro/Max; lo stato di ottobre 2026 dei bug di montaggio cartelle; la lettura di `AGENTS.md` da parte di Cursor; le ultime circa 16-19 KB delle pagine Desktop e MCP della documentazione (compresa la sezione "Coming from the CLI"). Il tuo piano (Pro o Max) non è stato assunto.

## Conclusione

Il risultato più utile di questa ricerca è un cambio di prospettiva: la domanda "come faccio parlare la Chat con Claude Code" ha una risposta tecnica fragile, mentre la domanda "dove vive la memoria" ne ha una robusta. Chat, Cowork, Code e Cursor non condividono i loro archivi, e nessuna delle richieste aperte promette di unificarli a breve; ciò che condividono sono i file. Come una casa con quattro porte e una sola cucina, conta poco da quale porta si entra se tutti trovano lo stesso tavolo apparecchiato. Per te, con materiale clinico a portata di mano, il vantaggio collaterale è decisivo: una cartella piccola, in chiaro, ispezionabile, da cui le cartelle cliniche sono escluse a monte, è più facile da difendere di qualsiasi ponte che dia una shell a una chat.

Se vuoi, potrei preparare i file di partenza (`AGENTS.md`, `CLAUDE.md` con `@AGENTS.md`, una struttura `memoria\` e la voce JSON del server filesystem limitata a `C:\Users\Tommi\Workspace`) e un controllo di quale file di configurazione l'app MSIX legge davvero. Richiederebbe di creare la cartella e di modificare `claude_desktop_config.json` sul tuo PC, con un backup preventivo. Per procedere, scrivi « Ok cartella canonica ». Un « ok » generico non vale come approvazione.
